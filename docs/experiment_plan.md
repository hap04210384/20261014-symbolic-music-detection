## G1 数据管线与登记

- G1.1 GigaMIDI 下载、`data/README.md` 登记 URL/版本/SHA-256/许可条款
- G1.2 三档抽样子集：10k / 100k / 1M 文件（固定 seed，名单入库）
- G1.3 预处理：MIDI → 事件集表示（onset, pitch, duration, channel）→ `data/processed/`
- G1.4 网格量化参数初步扫描（供 E5.7 用）
- **验收**：子集名单 + 校验和入库；随机抽 20 文件人工听/看谱确认解析正确

## G2 基线复现

- G2.1 SIATEC 实现（文献复现，验证：小样本输出与文献一致）
- G2.2 COSIATEC 实现
- G2.3 n-gram 钢琴卷帘哈希 + Jaccard
- G2.4 旋律轮廓编辑距离
- G2.5 MERT 嵌入 + 余弦检索（MelodySim 式，HuggingFace 权重）
- **验收**：每个基线在 100 曲小样上跑通，输出格式与 ours 统一（命中片段 + 定位 + 分数）

## G3 引擎移植与接口

> 约束：两个引擎仓库支撑在投论文（AnyFIM / TensorFIM），**审稿期间不得改动上游仓库**；
> 一切适配与优化一律实现在 B 自己的适配层，不动引擎本体。

- G3.1 事件集表示 → AnyFIM anytime 调度适配（查询接口、停止接口、命中输出）
- G3.2 BMMA 位图匹配核接入（wave batching）
- G3.3 MD5 验证协议接入（结果可复现）
- G3.4 小规模 sanity check：100% verbatim 检出
- G3.5 **稠密 ID 重映射**（2026-10-11 作者指示）：适配层在喂数据前按项支持度推导"会存活"的项集，做 原始ID↔稠密ID 双向映射，输出命中后反映射；引擎内部裁剪逻辑不改、行为等价
- **验收**：小规模 planted set 上 verbatim 召回 = 100%，且 anytime 停止接口按设计工作；
  G3.5 附加硬验收——重映射前后引擎输出项集逐集合一致（沿用 TensorFIM gold 校验纪律）；
  E4/E5 默认配置 = 开重映射，另存 off 对照组量化收益

## E1 检测性能主表

**协议 v2（A 方案）**：ours = detector（L = 最少证据项数，k-容噪）；
基线 = G2 全家 + FIM 引擎（可行阈值）。

- E1.1 planted-copy 全矩阵：6 变换（verbatim/移调/变速/音符分裂合并/换乐器删声部/转录往返）× 3–5 强度 × 4 长度（2/4/8/16 小节）
- E1.2 与 G2 全部基线对比：recall / precision / F1 / ROC-AUC，5 seeds 95% CI
- E1.3 困难负例集：风格相似无复制对（时长加权 PC 直方图 + 音区 + 力度余弦
  取最相似 20 曲，去除 verbatim 证据 ≥30 的真重复/翻唱），报误报率。
  **实测发现（2026-10-12，v2，236 片段）**：单层项集包含不能做决策——
  tolerant 层 frag-FP 93%、供体 top-20 仅 37%（变体匹配抬高了风格同类）；
  verbatim 层排序好（top-20 93.7%、margin p50=45）但 frag-FP 仍 22%。
- E1.4 结构确认（新实验，由 E1.3 发现驱动）：有序锚链 LCS（音高/时值/IOI/力度
  四维容差内的一对一保序匹配，Fenwick 链 DP）作为确认层。
  **实测**：严容差 k=(1,0,0)、ρ=0.5 → frag-FP 2.1%、召回 83.9%（转录噪声下），
  验收 <5% 达成；ρ=0.4 → FP 7.2%、召回 98.3%。系统定型为
  容忍筛查（可证明召回）→ 严格结构确认（决策级精度）两层，无需嵌入。
- **验收（硬）**：verbatim 召回 = 100%（detector 构造保证，实测必须 100%）；
  k-容噪内 near-verbatim 召回不低于 E2 理论下界；两级系统在 E1.3 困难负例上
  误报率 <5%@片段级（E1.4 实测 2.1%@ρ=0.5）
- 产出：论文主结果表

## E3 anytime 行为

**协议 v2（A 方案）**：anytime 曲线来自 detector 稀有优先调度（按查询项处理比例
采样停止点），不完备界 = { i : cnt[i]+U ≥ L }。

- E3.1 命中数/召回 vs 处理项数曲线，多停止时刻采样（附带每时刻不完备界）
- E3.2 同预算对比：稀有优先 vs 随机顺序 vs 热项优先 的召回-时间曲线
- E3.3 停止界质量：报告界 vs 真实漏报数（界要紧）
- **验收**：稀有优先显著优于随机/热项优先；界全程有效（真实漏报 ⊆ 界）
- 产出：论文图 3

## E5 组件消融（全面版）

**协议 v2（A 方案）**：消融对象调整为 detector 组件；FIM 引擎列为外部基线。

- E5.1 索引表示：倒排数组 vs 位图（内存-速度权衡）→ 位图加速证据
- E5.2 计数累加：numpy 逐项 vs 批量波（BMMA 式）→ 吞吐
- E5.3 稀有优先 vs 频率随机序 vs 热项优先 →  anytime 质量
- E5.4 L（最少证据项数）敏感性：L 偏离语义值 10%/25% 时召回/误报变化
- E5.5 容噪机制：k=0/1/2/3 扫描；每位置容噪 vs 全局容噪；只容音高 vs 只容时值 vs 联合 → 召回-误报-时间三维
- E5.6 MD5 验证协议开销占比（目标 <5%）
- E5.7 网格量化粒度（125ms/250ms/500ms）对召回-速度的影响
- **验收**：每个组件差异可解释、与论文声称一致；E5.3 完备性等价（同一命中集）必须成立（硬）
- 产出：消融表 + 1–2 张图
